# 知衡 0.4.19：单对话原生导出与摘要确认归属

日期：2026-09-26。继续审阅 0.4.18 后的两个核心流程，修复确认归属和 APK 导出链路。没有读取或修改项目 `.data` 中的真实健康资料；回归、页面流程与真实模型测试均使用虚构资料和隔离存储。

## 本轮修复

- **APK 单对话导出缺少原生保存入口。** 原先只有设置页的完整导出、备份接了 Android 系统文件保存器，“导出本对话”仍使用浏览器 Blob 下载。现在页面传递点击时选中的会话 ID，原生仅从本机带认证的 `/api/conversation-export` 取回该对话 JSON，再用系统保存器选择位置。浏览器保留下载流程，同时固定点击时的 ID，避免请求期间切换对话导致文件名归属错误。
- **保存结果如实提示。** 原生保存器取消不提示成功；系统保存器缺失、导出请求失败、写文件失败均可重新导出，临时文件清理。写入及流关闭成功后才提示“文件已保存”。原生请求禁止跟随重定向，继续受本机来源校验约束。
- **摘要确认错误跨对话生效。** 已通过回归复现：对话 A 显示摘要后，在 B 回复“可以”，会把 A 的摘要标记为确认；同一对话插入无关问题后回复“可以”也会误确认。现在确认必须对应本对话最后展示摘要的那一轮，并匹配事实摘要版本。事实更正后仍须重新确认。切换到其他对话、再回原摘要直接确认的正常路径保留；旧版本摘要没有会话字段时也须通过原回复关联校验。
- **无上下文的肯定回复。** 真实模型测试发现，新对话只说“可以”仍可能被模型扩写成整套饮食/活动建议。现在这类新对话先本地澄清意图，状态明确为 `local`，不调用模型猜测请求、不保存方案。
- 摘要中的 `sleep_schedule` 字段名改为“睡眠作息”。

## 验证与实际边界

- 基线 254 项 Python 回归通过；新增跨对话、话题打断、返回原对话确认三个场景，最终 **257 项通过**。
- 隔离 Edge 390px 页面流程通过：单对话下载、历史会话范围、原生桥接传递当前会话 ID、原生分支不触发 Blob 下载且不提前提示成功；大图上传、报告编辑、明确摄入确认与撤销、损坏图片错误提示通过。
- 高噪声合成 JPEG 压缩流程通过：原图 3,402,389 字节，处理后 data URL 582,483 字符，低于 716,800 上限；本轮没有新测真实食物识别精度。
- Node 语音回归通过；这仍是模拟权限/回调测试，不是手机录音测试。
- 当前真实模型完成虚构资料的摘要确认流程：先生成待确认摘要 → 在另一对话说“可以”保持未确认且本地澄清 → 返回原对话确认，保存一个计划。最终一次计划包含一项行动。测试入口：`tests/qa_summary_confirmation_live.py`。
- **真实模型输出质量未验收通过。** 同条件前一次回复仍把“只安排一项观察行动”扩展为多项建议；最终一次虽保存一项行动，正文仍把 2026-10-03 写成“下周五”（实际为周六）。当前测试断言的是确认状态与保存结果，不代表数量约束、解释依据或日期措辞已全面正确。后续应检查正文与结构化计划的日期/行动一致性，不能只看 `connected`。
- Android release 与 lintVital 成功；从最终 APK 读取内置配置，在宿主机隔离存储下调用模型并保存一条虚构体重记录成功。这不是 Android 网络或系统保存器真机验证。
- 当前 `adb devices` 无设备；**原生系统保存器、取消后重试、真机拍照和语音仍待手机验收**。浏览器桥接模拟只证明页面调用契约。
