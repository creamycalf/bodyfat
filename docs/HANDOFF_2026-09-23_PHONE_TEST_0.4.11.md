# 知衡 0.4.11：持续营养管理 P0 首轮手机测试包

日期：2026-09-23。依据 `NUTRITION_AGENT_PRODUCT_DECISION_2026-09-23.md` 实施手机体验的首轮修复。P1 的指南依据卡、P2 的真实菜单接口与 P3 的长期局部修订尚未完成；此包不能证明临床建议质量。

## 本轮行为

- 移除首次计划自动改为“明天开始”的规则。用户明确指定明天或其他日期仍按原意执行；今天的饮食计划先核对已经吃过的餐次和下一餐可选项，已过餐次不补做。
- 保存计划后保留模型对当前问题的自然回复，只追加真实保存回执。下一步引导从可执行的计划行动生成，作为可选反馈；页面不再展示旧版固定的起床、早餐清单。
- 饮食计划的自做和外卖选项独立选填。界面只展示实际提供的选项；外卖搜索词标成待核对的搜索建议，不声称附近可买。没有菜单时提示用户发送正在看的候选。
- 普通问答和单餐交流使用较短的模型契约。真实模型仍偶尔输出长清单、未经核实的克数或商家筛选；这类选餐回复由程序改为依据本轮时间、偏好和菜单状态的保守下一步，不影响事实保存。完整个体方案仍走既有资料确认与安全门槛。
- 内置模型构建在缺少接口或模型名称时明确失败；未修改密钥来源或手机存储。

## 验证

- 224 项 Python 回归通过；包含今天餐次核对、明确指定明天、用户临时改期、可选行动引导、计划第三天复盘分流和无真实菜单的输出约束。
- 390px Edge 隔离流程通过：档案保存与刷新、计划页、照片发送后上传、报告修改、摄入确认与撤销、错误提示。计划页截图为 `tmp/nutrition-flow-plan-mobile.png`。
- 对指定远程模型用隔离的合成资料测试了晚间无菜单点外卖、早餐已知后询问午餐、夜班下班且不想做鱼，以及计划第三天遇到加班后讨论今晚外卖。四种场景均连接成功，最终回复未切到明天、重问长问卷或声称附近商家可买；第三天场景接住了未完成的散步且未误打卡。模型原始单餐回复有过长清单和未经核实数值，因此触发本轮输出回退。测试只覆盖这几种场景，不能代表长期对话质量。
- Android 离线 `assembleRelease` 成功。APK 包名 `cn.zhiheng.mobile`，`versionCode=19`，`versionName=0.4.11-test`；与 0.4.10 的签名证书相同。包内包含最新源码、指定基址 `http://47.110.38.211:8080/v1`、模型名称和密钥配置，不含项目 `.data` 健康资料或签名密钥。源码资源目录的临时明文配置已清理。
