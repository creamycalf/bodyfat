# 知衡 0.4.14：APK 语音与连续健康访谈

日期：2026-09-24。用户确认截图来自知衡 APK。本轮针对麦克风故障，以及只问基础数字便提前给减重建议的问题。私人测试包，尚未完成手机实测；不代表完整私人营养师能力已验收。

## 原因与修复

- 原语音依赖 WebView 内浏览器语音识别，错误提示仍指向浏览器地址栏。APK 增加 RECORD_AUDIO 声明与运行时申请，并优先通过 Android RecognizerIntent 调用系统识别服务；结果只写入输入框，用户核对后发送。拒绝权限、无识别服务、取消均保留原草稿，并提供相应提示。系统语音服务可能联网；无服务时可使用输入法语音。浏览器入口仍保留。
- 原资料门槛主要约束正式方案保存，聊天正文仍可提前输出具体建议；短回答也可能丢失个人减重访谈上下文。现在保存会话咨询类型，恢复编号式回答的访谈上下文，并对聊天正文应用资料检查。
- 基础数字后优先核对既往/现有疾病、限制、用药、过敏与手术史，再了解目标、饮食各餐、零食饮料和睡眠作息。回答“没有”关联实际上一问题，不将“不清楚”、跳过、空列表视为已确认没有疾病。旧档案中的空列表可能因此被重新核对。
- 当前修复保留普通知识问答打断访谈的能力，调整过度限制回答长度的回退规则。它仍有规则回退，不能把这轮修复描述为已经具备自然、长期、全面的营养师判断。

## 验证与边界

- 235 项 Python 回归通过，包括截图式编号续答、连续四项健康信息、未知信息、普通问题打断、提前建议拦截。
- Node 语音测试通过：草稿保留、权限错误、取消与迟到回调、原生桥接结果；这些是模拟测试，不等于手机音频测试。
- 隔离窄屏 UI 流程通过，覆盖年龄录入、图片、报告编辑、访谈确认、撤销与错误展示。
- 真实配置模型完成六轮虚构资料测试：开始减重 → 基础资料 → 病史 → 用药 → 过敏 → 手术。每轮连接成功，无错误，无提前保存计划；之后继续询问目标和生活背景。未做不同模型的同条件比较，因此不把问题归因于某个模型，也不保证所有自然表达均已覆盖。
- Android release 编译与 lintVital 通过。当前无 adb 设备连接，首次授权、永久拒绝后恢复、具体手机系统语音服务及识别质量仍待用户实测。
- “未知资料下提供有边界的起步帮助”仍需单独验收，尤其应避免反复追问用户明确不愿回答的信息。长期跟进、方案质量与依据也不由这次六轮访谈测试证明。
