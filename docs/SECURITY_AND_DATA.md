# 数据、隐私与安全边界

## 1. 数据分类

| 数据 | 位置 | 是否进入模型上下文 |
|---|---|---|
| 个人资料 | `.data/profile.json` | 仅白名单字段 |
| 健康记录 | `.data/records.json` | 仅已确认、允许记忆且检索命中的记录 |
| 对话历史 | `.data/conversations.json` | 当前请求只携带前端最近 6 条；长期历史不自动全量发送 |
| 媒体元数据 | `.data/media.json` | 不自动进入文本记忆 |
| 原始图片 | `.data/media/` | 图片分析时发送给配置的视觉模型 |
| API Key | 环境变量或 `config.json` | 仅用于后端鉴权，不返回前端 |

所有 `.data/` 文件目前都是明文。

## 2. 已实施保护

- 服务只监听 `127.0.0.1`；
- CORS 只允许 `localhost:8787` 和 `127.0.0.1:8787`；
- `config.json` 和运行数据不应提交；
- 配置状态接口只返回是否存在 Key；
- 模型记忆需要记录已确认且未关闭记忆权限；
- 记忆检索和排序在本机完成；
- 模型系统提示明确把记忆视为不可信用户数据；
- 结构化记录、资料字段、图片文件头及声明格式经过校验；
- 图片宽高限制为单边不超过 20000 像素，默认总像素不超过 4000 万，降低超大尺寸图片的资源消耗风险；
- 删除记录、对话、媒体和全部数据需要显式确认；
- 媒体删除会校验目标仍位于 `.data/media/`；
- 未确认媒体按期限清理；
- 紧急关键词优先本地处理；
- 日志不输出 API Key 或完整上游响应。
- 页面与 API 使用 `no-store`、CSP、禁止 MIME 嗅探、禁止 iframe 嵌入和无来源引用等响应头。

## 3. 当前风险

### 无身份认证

任何能访问本机 8787 端口的进程都可能读取或修改数据。CORS 不是身份认证，不能替代登录或会话令牌。

### 明文存储

健康记录、资料、对话和图片均未加密。系统账户被攻破、磁盘被复制或备份泄露时，数据可能暴露。

### 第三方模型

发送给模型的文字、检索命中记录和图片会离开本机，受模型服务商及中转服务隐私政策约束。当前验证地址属于第三方 OpenAI-compatible 服务，不应默认视为医疗数据合规环境。

### 请求体与滥用防护仍有限

应用层已在读取前统一限制 JSON 请求体，默认 12 MB、可配置范围 1–32 MB；图片解码后另有大小限制。服务按来源地址实施基础每分钟限流，默认 240 次、可配置 30–1200 次。未来如改变可信本机部署边界，仍应在反向代理层设置独立限制。

### 非医疗器械

规则和模型可能遗漏风险或产生错误建议。当前系统不能用于诊断、处方调整或替代急救。

## 4. 删除语义

- 删除健康记录：从 `records.json` 移除；
- 删除对话：只移除对应对话，不级联健康记录；
- 删除原图：删除文件及媒体元数据；
- 清空数据：删除资料、记录、对话、媒体元数据和媒体目录中的文件；
- 关闭记忆：保留记录，但后续检索与模型上下文不再使用该记录。

当前没有安全擦除保证，磁盘、系统快照或外部备份中可能仍有副本。

## 5. 上线前安全设计顺序

1. 明确单机单用户、局域网或公网部署边界；
2. 设计账号、会话、权限和多用户目录/数据库隔离；
3. 设计密钥存放、轮换、丢失恢复和数据迁移；
4. 再实施静态加密，避免先加密后无法恢复；
5. 在反向代理层增加请求大小、速率、并发和来源限制；
6. 增加可脱敏的审计日志、备份和恢复演练；
7. 对医疗安全规则、提示词和高风险场景单独评审。

## 6. 使用建议

- 只在可信电脑上运行；
- 不要把服务端口转发到公网；
- 不在聊天、截图或仓库中暴露 Key；
- 敏感图片分析后，如无需原图应立即选择“不保留”；
- 定期离线备份 `.data/`，并保护备份介质；
- Key 曾泄露时应在服务商侧撤销并重新生成。
