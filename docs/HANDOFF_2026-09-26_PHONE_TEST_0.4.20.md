# 知衡 0.4.20：对话归因实测与程序误改写修复

日期：2026-09-26。用户希望获得自然、连续、能接住话题的咨询体感，要求按“同一对话、原始回复与最终回复、另一模型对照”的思路继续。本轮没有更换默认模型，未读取或改动生产 `.data`。

## 判断

**模型和应用均有问题。本轮修复了可复现的程序错误，但对话体感仍未验收通过。** 尤其不能把八轮连接成功或 267 项回归通过解释成建议可靠、接近自然营养咨询。

## 对比方法和证据

测试入口：`tests/qa_dialogue_attribution.py`。八轮固定虚构语句涵盖：想瘦一点但坚持不了计划、晚下班只能外卖、拒绝性别、纠正下班与到家时间、询问跳过晚餐、要求先解释饥饿、他人餐食归属、继续但不重复拒答。

修复前每次模型调用分别用 `claude-opus-4-8` 和已有备选 `claude-opus-5` 处理**相同的消息和事实上下文**，对比原始文本；只让当前模型的结果进入应用和下一轮历史。格式修复调用也同时探测，但统计首次 JSON 时不混入修复请求。模型名称是当前服务报告的标识，不代表已独立验证上游供应商或型号。没有新增外部服务。

- 八个首次响应，当前模型有 **6/8** 可解析为 JSON，备选 **8/8**。当前模型两次出现引号未转义，修复后其中一次仍失败，最终一轮向用户显示结构化失败。备选在这个小样本的格式遵循上更好。
- 两个模型首轮都列了多组问题；备选仍存在长清单、追问过多和过度确定的生理解释。不能由这八轮宣布某模型总体更强。
- 当前模型在未测血糖时写出“已经处于低血糖状态”；备选也编造了具体时间点的生理变化。这里记录的是**错误输出实例，不是医学事实**。
- 当前模型收到“只能叫外卖”的生活描述后，应用将回复改为固定“家常饭或面食、提供菜单”的模板，丢失原本的接话。程序把“好，那继续吧，别再问刚才不想说的了”保存到了 `lunch_habit`。
- 确认拒答只识别裸“跳过”，而简化提示词还丢掉了 `skipped_fields`。用户自然地说“不想说”没有持久状态支持。

报告均仅含虚构测试内容，不含配置/密钥、生产档案或模型隐藏推理：

- `tmp/dialogue-attribution-before.json`：原版配对对照；
- `tmp/dialogue-attribution-after.json`：中间迭代，不能当最终源码验收；
- `tmp/dialogue-attribution-final.json`：最终源码、当前模型、八轮功能边界检查通过。

比较限制：固定语句未根据每个模型的追问分叉，备选继承当前模型的历史；没有独立多周生活轨迹、统计重复或真机主观评分。修复后上下文随程序变化，不是与修复前逐 token 相同的模型能力评测。

## 已实现修复

1. “想瘦一点”等自然说法进入初诊契约，而非误落入通用流程；普通营养问题仍可打断初诊。
2. 不再把出现“外卖”直接当成选餐请求；无菜单本身也不再成为整段替换的理由。安全的、围绕当前困难的回答保留；编造“附近有／直接点这家”、配送时间、评分、未经核实营养等仍受校验。
3. 新增有来源的 `interview.declined_fields`，识别明确字段拒答及对上一字段的自然拒答，传入所有模型分支。只改变接下来可问的问题，不将未知视为健康事实，不放宽正式计划准备度。拒答字段问句被移除时尽量保留其余解释；用户自愿补充仍可记录。
4. “继续吧”“别再问”“先解释／为什么”等话语不再作为短答案填进饮食或健康字段；同样拒绝模型把这种当前原话写成档案值。无问号的解释请求也不能误关闭已提问主题。
5. 反思两餐相隔“10小时”不再自动命中运动时长处方拦截；正式运动处方、饮水定量和未经核实营养限制保留。普通解释可以不以新问题结尾；明确要求逐字段建档的旧流程仍兼容。
6. 补上“200–300卡”这种简称的营养数字校验漏洞；卡片等普通词不命中，删除不可靠数字句时保留其他回答。
7. 去掉晚下班兜底中未由本轮提供的“久坐”表述；提示词明确不凭餐次间隔编造个人血糖、激素及代谢结论，但**提示词并未消除全部错误推断**。

新增回归在 `tests/test_dialogue_attribution.py`。先复现 5 个失败，再修复并保留负例；另覆盖解释请求入档、继续/拒答的短答案与“卡”单位。

## 最终验证及尚未关闭的问题

- **267 项 Python 回归通过**，包含既有安全计划拒绝、摘要确认、事实来源及幂等测试。
- 390px 隔离 Edge 页面流程通过：当前与历史会话导出、原生桥接 ID、图片分析、报告改重量、确认摄入、撤销、无溢出。页面模型是受控模型，不代表视觉识别精度。
- 最终八轮真实模型测试均 `connected`，其中两轮用了 JSON 修复；没有保存计划，性别保持未知，拒答状态保留，没有把继续/解释请求写入餐食和健康字段。
- **对话质量检查未通过**：第一轮仍需程序压缩多问题输出，部分回复仍过长；最终模型仍把“九点下班”说成“九点到家”，纠正后才按十点处理；仍出现未经依据支持的生理时间线与“节能模式”解释。提示词要求不能当作执行保证。
- 最后一轮仍可能被程序拉回健康资料提问；仅删除误拦截和增加拒答状态不足以形成自然对话管理。
- 混合“别人吃的＋我自己吃的”句子仍受保守的整句人物过滤影响，可能未入档；模型口头承接不代表完成保存。下一轮需单独做分句归属与更正，不直接放开整句过滤。
- 0.4.19 记录的计划数量、日期/星期一致性问题未在本轮全面修复。食物来源覆盖、真机导出、语音、实际餐图质量和 P1–P3 路线仍未关闭。

下一步应把“真实输出质量”作为门槛，重点评估简化对话与后台结构化整理的职责、对过强断言的约束，以及候选模型在独立连续对话上的表现。不要再只增加提示词、机械兜底，或用一次成功回复宣称达到目标。
