# 当前模型服务的实测对比

日期：2026-09-26。用户明确要求忽略官方型号对应关系，只测试现有服务的实际行为。所有名称均按服务别名处理，不由返回的 `model` 字段证明上游身份。本轮只测试，未更改默认配置、源码业务行为或重打 APK。

## 方法

1. `tests/qa_service_candidates.py`：四个服务别名，每个分别对三个相同虚构上下文执行纯文本与 JSON 输出，共 24 次请求。场景为首次咨询、纠正时间并只求解释、纠正本人/同事餐食且不继续追问。短提示词保持一致，最多三个请求并行，无自动重试。
2. `tests/qa_dialogue_attribution.py`：候选各自运行现有 0.4.20 完整八轮对话，历史由自身实际回复组成；检查用户拒答、事实记录、计划不应提前保存，同时人工看原始回复和应用最终回复。
3. 仅虚构数据和临时存储，不读取生产 `.data`，不保存密钥或配置。原始报告只保存可见输出，不含隐藏推理。

## 24 次相同上下文筛选

| 服务别名 | 返回成功 | JSON 场景可解析 | 六次响应耗时中位数 |
|---|---:|---:|---:|
| claude-opus-4-8 | 6/6 | 3/3 | 5.73 秒 |
| claude-opus-5 | 6/6 | 3/3 | 6.82 秒 |
| claude-sonnet-5 | 6/6 | 3/3 | 6.51 秒 |
| claude-fable-5 | 6/6 | 3/3 | 6.06 秒 |

JSON 可解析统计允许去掉 Markdown 代码围栏，不等于严格裸 JSON 合规，更不代表字段语义正确。未提供档案字段枚举，因此不以其字段名称评优劣。

四个名称均有相同的重要失误：

- 用户要求“只回应这次更正”，纯文本和 JSON 场景都继续追问晚餐或份量，未尊重停止追问的要求。
- 时间纠正场景中，结构化输出引用前轮年龄、身高作为“本轮原文”，违背证据范围；部分 evidence 拼接了原文中不连续的语句。
- 在只知道进食间隔的情况下，仍输出个人血糖/能量储备的确定性推断。记录这些输出作为质量问题，不将其当医学事实。

短提示词下回答明显短于部分应用内回复，但两种输出格式都存在语义失误。因此不能认定“只拆掉 JSON 就能解决”，也不能按名字认定换成 5 就升级了实际质量。

原始记录：`tmp/service-candidates.json`。

## 独立连续对话

本轮三个候选均完成独立八轮并通过 `--check`；原默认模型引用同一版程序此前的八轮报告作参考，并非本轮同步重跑。

| 服务别名 | 八轮连接成功 | 模型调用数 | 每轮首次调用耗时中位数 | 对话表现 |
|---|---:|---:|---:|---|
| claude-opus-4-8（此前基线） | 8/8 | 10 | 7.57 秒 | 有修复调用；仍有模板回答、过度确定的生理解释 |
| claude-opus-5 | 8/8 | 8 | 8.98 秒 | 开场被程序改成资料追问；只求解释时提前给建议，仍推断具体血糖变化 |
| claude-sonnet-5 | 8/8 | 8 | 7.84 秒 | 开场更能接住坚持困难，但第三轮编造九点半到家，后续反复追问外卖 |
| claude-fable-5 | 8/8 | 8 | 7.89 秒 | 未见明显优势；时间表述混乱，仍推断下午三四点血糖开始低 |

检查通过仅代表本轮预设边界：没有提前保存计划、拒答被记录且没有写入性别、指定的闲聊短句未混入餐食/健康字段等。它不代表所有事实记录正确或回答质量达标。三组八轮均没有保存计划，但回复文字仍可能提前安排饮食建议。

`opus-5` 第六轮把午餐后的能量耗尽、血糖下降、糖原消耗和饥饿激素串成个人确定时间线；第七轮仅凭“吃面”就解释饱腹时间。这些是缺乏个体证据的输出。`sonnet-5` 的较好开场不能抵消虚构到家时间；`fable-5` 同样没有解决此类问题。以上错误均不作为健康建议。

原始记录：`tmp/dialogue-claude-opus-5.json`、`tmp/dialogue-claude-sonnet-5.json`、`tmp/dialogue-claude-fable-5.json`；此前基线为 `tmp/dialogue-attribution-final.json`。

## 本轮结论

这些服务别名均能调用，但没有测出足以支持切换默认模型的质量提升。暂保留 `claude-opus-4-8`，并不表示现有模型已经合格。若后续继续试聊，可优先复测 `sonnet-5` 的开场表现，但目前不能称其整体更好。

对话体感同时受模型和应用处理影响：原始输出已存在不遵循当前意图、虚构细节和过度解释；应用又会把部分开场替换成资料采集模板。因此，单纯换服务别名没有解决问题，也不能把全部问题归到模型。后续改动应对照原始输出与最终回复，分别验证当前意图处理和模板替换，再用新的虚构情境复测，避免仅适配固定八句。

## 限制

每个场景只有一次采样，模型间不完全同时执行；延迟包含网关排队、网络和生成长度，非性能排行榜。八轮语句固定、未按回答自适应，不是用户真机自然交流。相似错误和措辞不能证明后台为同一模型；也不能凭这些测试验证其真实供应商、路由或型号。
