## 3. 已完成范围

### 模型与稳定性

- OpenAI-compatible 文本和视觉调用；
- 明确协议、超时、并发限制和有限重试；
- 请求 ID、耗时、尝试次数和安全错误码；
- 鉴权失败不重试，429/5xx 才有限重试；
- 模型失败时回退本地规则。

### 健康数据流程

- 对话提取候选健康字段；
- 确认前编辑睡眠和体重；
- 1–20 条原子批量确认；
- 120 秒一次性撤销；
- 单条修改和删除；
- 近 14 日真实体重趋势；
- 基于真实记录并显示依据的今日建议。

### 记忆和资料

- 资料字段白名单和范围校验；
- 逐条记录记忆开关；
- 本地类型、关键词和时间相关性检索；
- 单次最多 12 条裁剪记录进入模型；
- 对话返回并展示记忆命中原因；
- 个人页提供记忆搜索；
- 真实对话摘要和单独删除。

### 图片与隐私

- 上传前确认发送给视觉模型；
- 支持 JPEG、PNG、WebP、GIF；
- 图片大小默认不超过 8 MB；
- 分析后确认保留或立即删除；
- 未确认原图按期限清理；
- 删除路径限制在媒体目录；
- 数据导出和全部清空。

## 5. 已知问题和风险

### P0：上线阻断

1. 没有账号、会话鉴权和多用户隔离；
2. `.data/` 明文保存健康数据和图片；
3. 当前本机 `config.json` 直接保存 Key，`key_value_exposed_in_config` 为 `true`；
4. HTTP 请求体读取前没有统一大小上限；
5. 没有自动备份、恢复演练、进程守护和运行监控；
6. 医疗安全规则只覆盖有限关键词，未经正式安全评审。

### P1：产品完整性

1. 记忆检索是关键词和类型排序，不是向量语义检索；
2. 饮食数据不足时不会计算热量和蛋白质余量；
3. 已确认图片没有缩略图预览和自定义保存期限；
4. 历史对话只展示摘要，尚无完整详情页和搜索；
5. 数据模型没有版本迁移机制。

### P2：代码维护

1. `index.html` 仍是单文件脚本，后续应拆分；
2. `server.py` 路由采用手写分支，复杂度继续增长前应模块化；
3. 当前 JSON 文件方案不适合多进程或多用户并发；
4. 旧文档中包含已经失效的模型连接结论，仅作历史参考。

## 6. 建议下一步

推荐按以下顺序继续：

1. 增加请求体总大小限制和配置值校验；
