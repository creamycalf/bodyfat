# 知衡项目交接文档（2026-09-03）

## 当前结论

暂不实施登录体系，当前目标是把可信本机上的单用户使用流程跑通。文本对话、候选确认、看板刷新、档案修改、资料保存、记忆搜索、导出和撤销已经通过隔离 HTTP 与浏览器验收。

正式入口仍为 `server.py`，本地地址为 `http://127.0.0.1:8787/`。本轮验收没有修改正式 `.data/`。

## 本轮完成

- 只允许 `/` 返回前端页面，`/config.json`、`/server.py` 等根目录文件不再能被 HTTP 下载；
- JSON 请求体默认限制为 12 MB，可用 `storage.max_request_mb` 配置，允许范围 1–32 MB；
- 非 JSON、无效 JSON、无效 `Content-Length` 返回明确的 4xx 错误；
- 模型返回的未知记录类型会在后端丢弃，前端候选类型使用固定文案，避免注入；
- 资料、媒体元数据和清空流程补齐组合操作锁，降低多线程覆盖风险；
- 档案修改从浏览器 `prompt()` 改为页面内联编辑；
- 数据导出改为挂载临时下载链接并延迟释放 Blob URL，兼容下载较慢的浏览器；
- 自动化测试增至 15 项，新增完整单用户 HTTP 流程和敏感文件拒绝访问验证。

## 已验证流程

1. 输入“昨晚23点睡，7点起，体重80kg”；
2. 得到睡眠 8 小时、体重 80 kg 两条候选；
3. 批量确认后看板显示 2 条记录和最新体重；
4. 在档案中把体重内联修改为 79.5 kg；
5. 保存测试资料；
6. 搜索“最近体重”，正确命中 79.5 kg 并显示匹配原因；
7. API 导出成功，批量撤销成功；
8. `/config.json` 返回 404。

随后又完成一次包含图片的浏览器全流程验收：3 条首批记录、第二次体重趋势、档案内联修改、2 段历史对话、个人资料、记忆搜索、测试餐盘图上传与确认保留、数据导出均正常；页面控制台无错误。远程 AI 在隔离环境中刻意关闭，因此图片分析验证的是安全降级路径，而非真实视觉模型质量。

最后使用无敏感测试文本和合成餐盘图补做真实接口验收：当时请求模型名为 `claude-opus-4-6`，文本与视觉请求均返回 `ai_status: connected`，无安全错误，文本回复与图片分析内容均非空。此结果只能证明接口连通，不证明第三方中转实际使用的底层模型。当前配置后来已改为 `claude-opus-4-8`。测试数据、临时 Key 副本、隔离服务和 8788 端口均已清理。

- 对话现在使用稳定会话 ID；同一新对话中的多轮消息追加到同一条历史记录，点击“新对话”会真正清空当前上下文并创建新的会话边界；
- 历史页增加全文搜索和完整对话详情，旧的单轮历史仍可读取、搜索和删除；
- 修正“23点半睡，7点起”等半小时睡眠计算，也支持“睡了6.5小时”的时长表达；
- 缺少有效时长的睡眠候选不再显示为 0 小时，也无法通过 API 写入；
- 新增睡眠解析、空时长拒绝、会话追加、详情读取和全文搜索回归覆盖。

## 对话可选资料表单

- 请求减脂/健康方案且基本资料不全时，返回简短邀请和“填写表单 / 先不填，用文字或语音说”选项；上游也可通过 `intake_form` 标记请求基本情况表单。
- 年龄、身高、体重、生理性别、目标、身体状况、过敏、用药均选填。已有资料预填，空白不覆盖。
- POST /api/intake 接受 profile、可选 weight_kg 和 confirm:true；保存前统一校验，确认后个人资料和体重档案分别落盘。
- 跳过后聚焦聊天框，当前页面会话不重复强制提供表单，模型提示词要求一次最多追问一个问题。
- 表单提交后自动发送确认摘要继续对话，并避免为已保存的表单数据重复生成确认卡。
- 隔离浏览器验证了跳过、部分填写、保存继续、重载预填；语音仍依赖浏览器支持及用户麦克风授权，未代替用户开启麦克风。

## 品牌身份回复与模型配置更新

- 当前文本与视觉请求模型名均已按用户要求改为 `claude-opus-4-8`。中转接口调用成功不等于底层模型身份已核实，此前换名后回复仍自称 MiMo。
- 聊天中识别到模型身份、密钥、接口地址、内部配置或系统提示词询问时，本地直接回复“我是你的知衡健康师。”，不读取健康记忆、不调用上游、不产生候选记录。
- 系统提示词增加相同品牌身份要求，紧急症状安全规则仍优先。
- 此功能是聊天回复策略，不是完整防泄漏或鉴权机制；配置状态 API 和运行诊断元数据仍为本机维护保留。不保证关键词规则覆盖所有变形提问。
