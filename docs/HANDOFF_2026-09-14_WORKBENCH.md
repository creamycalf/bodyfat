# 知衡工作台改造交接

2026-09-14。当前最新实施交接。设计依据为 PRODUCT_REDESIGN_2026-09-14.md；本文描述实际实现，未完成项不能作为已交付功能。

## 本轮已实现

- 新增 workbench.py：受校验的文字、列表、图文、体重趋势模块，稳定 ID、模块版本、来源和更新原因；模块与执行计划版本分离。
- 对话每轮可以评估页面和方案，不再要求必须命中“修改计划”关键词。模块按 ID 局部更新，相同内容不生成新版本；版本化事务、重复消息幂等沿用原实现。
- 默认首次了解改为对话，提供用户级已知信息/缺口给模型；表单通过 show_form 作为兼容辅助入口，不再默认强制弹出。档案显示逐步了解情况。
- 新增独立方案页，主导航为对话、今日、方案、档案，设置移至顶部。原有计划在方案页直接显示，今日保留任务与摄入汇总。
- 图文/文字模块由安全渲染器展示；文字支持有限标题、强调与列表样式，不执行模型返回的 HTML 或脚本。
- 食物照片通过关联会话和 media_id 判断 consumed/planned/reference/unknown；明确本人已吃且有原文依据才自动入档。准备吃、菜单、只有照片不自动计入摄入。后续修正更新同一图片的饮食记录；逐次确认偏好通过待确认按钮保留。
- 营养结构支持热量、蛋白质、碳水与脂肪范围；今日仅汇总实际饮食记录，显示缺少估算的记录数，不宣称完整全天摄入。图片参考估算与实际摄入分开展示。
- 图片可在聊天和档案查看，新增受路径校验的图片读取接口。分析失败可用 retry_id 重试原图，不重复上传。失败提示区分超时与没有结构化结果。
- 模块和修订保存于现有 workspace，随备份导出/恢复；撤销包含本轮页面与媒体判断，仍使用原全局版本保护。

## 尚未完成与后续优先级

1. 图片上游连续超时：进一步检查配置服务的视觉请求兼容性、延迟与能力；不得宣称拍照估算已完整可用，不擅自换模型或扩大真实健康资料传输。
2. 新增页面协议仍靠提示词和校验，格式失败提示并保持原页面；未实现持久后台评估任务、自动恢复未完成页面生成。
3. 首次访谈现在共享已有档案与缺口，但仍未实现完整的用户级跳过主题、阶段确认和持久下一问题状态机；“持续跟进”目前依据已有计划判定。
4. 一餐多图归并尚未实现，当前按图片ID关联单餐；营养标签/照片估算准确性需要更多真实视觉验收。尚无营养数据库、个性化目标预算计算或自动剩余额度。
5. 模块增改、同ID更新和历史已实现；自由排序、隐藏、固定模块与独立模块撤销界面尚未实现。当前来源记录删除或关闭记忆后，引用该记录的模块隐藏，未做智能重生成。
6. 图片按钮确认后不会自动再发一次方案评估；可在对话继续。截图验收不替代用户实际使用认可，真实麦克风验收仍未完成。
