# 知衡：对话驱动的 AI 健康管理助手

> 2026-09-07 产品方向已重新梳理：[需求重梳与产品改造方案](PRODUCT_REDESIGN_2026-09-07.md)。下一轮改造以该方案为基线，重点补齐对话生成持久计划、档案自动整理、看板执行反馈闭环；本文保留历史需求，部分确认策略和页面职责待随实施更新。

## 1. 产品目标

知衡不是固定作息表、运动打卡器或单纯卡路里计算器，而是一个对话驱动的个人健康管理助手。用户通过文字、语音和食物照片描述现实情况，系统将信息提取为结构化记录，经用户确认后写入档案，再根据当日状态、历史趋势和健康风险生成下一步建议。

核心闭环：

```text
用户描述现实情况 → AI理解和追问 → 用户确认 → 更新健康档案
→ 刷新今日看板 → 根据执行结果调整下一步建议
```

## 2. 目标用户与使用场景

第一阶段围绕以下需求验证产品，公开文档不包含个人健康画像：

- 希望逐步改善饮食、活动和睡眠，生活安排可能以久坐、加班或外卖为主；
- 对正式运动接受程度不同，需要结合时间、场地和偏好提供可执行选择；
- 可能有本人明确提供的病史、手术、过敏或检查限制，必须分别核对，不能推断；
- 目标是持续改善健康，而不是短期极端减重。

实际年龄、身高、体重和健康背景仅保存在使用者自己的本地资料中，不随源码发布。

## 3. 信息架构

底部固定四个入口：

1. **对话**：新对话、历史对话、快捷录入、文字、语音、照片。
2. **看板**：由已确认的对话和数据刷新；显示状态、趋势、剩余预算和当下最重要的一件事。
3. **档案**：按时间轴查看已确认事件，可按睡眠、饮食、体重、症状筛选；后续提供趋势图。
4. **我的**：基本资料、疾病/手术/用药、AI配置、隐私、数据导出。

## 4. 首次使用流程

首次使用不展示空计划，而是邀请用户选择资料采集方式。资料表单必须全部选填，用户也可以跳过并改用文字或语音。选择对话后一次最多追问一个对当前决定最有价值的问题，不以补齐全部资料作为使用门槛。

可采集内容包括：

1. 基本资料：年龄、性别、身高、体重、腰围、工作和作息。
2. 健康资料：手术、疾病、过敏、用药、化验结果和就医情况。
3. 生活约束：外卖频率、预算、口味、家庭和工作场景、可接受的最低行动。
4. 目标和边界：期望减重速度、不能接受的方式、通知偏好。
5. 系统展示“准备记住的内容”，用户确认/修改后才写入档案。
6. 生成临时方案：初始热量范围、记录方式、第一周只改变的一件事。

触发判断可由程序规则或模型结构化信号完成，但最终表单字段、校验、确认和写入必须由程序控制。详细交互见[可选资料采集流程](./OPTIONAL_INTAKE_FLOW.md)。

## 5. 日常输入

### 5.1 必填最小输入

- 每餐照片、文字描述或语音；
- 早晨体重（没有设备时手动输入）；
- 起床后的睡眠时长和主观精力；
- 异常症状发生时记录症状。

### 5.2 可选输入

- 饮料、酒精、零食；
- 饥饿感、压力；
- 步数和久坐；
- 腹胀、腹泻、喘息、关节痛；
- 血压、血糖、尿酸、血脂、TSH、FT4等化验结果。

## 6. AI能力

### 6.1 对话理解

每条用户消息同时生成自然语言回复和结构化候选数据。候选数据必须包含来源、置信度和是否需要确认，不能未经确认写入长期档案。

### 6.2 外卖/食物分析

照片分析输出热量和营养范围，而不是伪精确数字；指出最大不确定性，追问一个最有价值的问题（米饭、油、酱汁或实际吃了几成），再给出“现在吃多少、剩下怎么安排”的选项。

### 6.3 个性化决策

系统依据当日睡眠、精力、饥饿、已摄入、14日体重趋势、症状和执行难度，生成下一步建议。看板不生成固定作息表，不因单日超标要求惩罚性运动或断食。

### 6.4 AI记忆

长期档案、每日摘要、每周摘要和事件原文分层保存。对话回答优先检索相关摘要和近期事件，不能无限拼接全量历史上下文。

## 7. 健康安全边界

- 产品是健康管理工具，不作诊断、不调整处方、不替代医生；
- 哮喘明显加重、胸痛、呼吸困难、剧烈腹痛、急性红肿关节痛等触发就医提示；
- 甲状腺、尿酸、血糖、血压和肝肾功能异常时，停止自动激进减重建议；
- 胆囊切除相关胃肠症状只做记录和饮食耐受观察；
- 所有医疗相关建议显示依据、数据时间和“不确定性”。

## 8. 数据与隐私

- 用户拥有查看、修改、导出和删除权；
- 原始照片可设置保存期限；
- AI写档案必须二次确认；
- 首版无设备时以本地存储为主；
- 正式版 API 密钥只放服务端，不放在客户端；
- 每条数据记录来源：手动、对话、照片、设备或导入。

## 9. 第一阶段（MVP）

必须完成：

1. 移动端四入口和对话优先交互；
2. 首次访谈和结构化数据确认；
3. 文字、语音转文字、照片选择入口；
4. 本地数据持久化；
5. 对话历史按日期保存；
6. 健康档案时间轴；
7. 今日看板和14日趋势图；
8. 可插拔 AI 接口（默认平台托管模型）；
9. 基础风险规则和异常提示；
10. 数据导出和清空。

暂不做：

- 设备接入；
- 医生后台；
- 多人家庭账户；
- 复杂健身课程；
- 自动诊断和用药建议；
- 过度精确的照片营养估算。

## 10. 验收标准

数据采集、图片分类、体重/化验单 OCR、饮料、排泄和原材料处理的详细规范见 [DATA_SPEC.md](./DATA_SPEC.md)。

- 新用户可在5分钟内完成首次访谈并确认档案；
- 用户可在60秒内记录一餐；
- 一条睡眠对话确认后，看板和档案均更新；
- 新开对话仍能读取长期档案；
- 食物估算必显示范围和不确定性；
- 无设备时核心流程可完整使用；
- 删除数据后本地记录不可恢复；
- 所有异常健康提示可追溯到触发数据。
