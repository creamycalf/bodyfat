# 知衡 0.4.27：问答与图片完整流程修复

用户反馈图片超时，随后普通询问也难以使用。本次检查问答、持久化、图片队列、前端等待状态和 Android 请求链路；没有读取或修改项目 `.data` 中的真实健康资料。

## 已复现和修复的问题

1. 文字问答使用全局资料版本做保存检查，后台图片队列更新状态也会递增版本，导致已拿到的文字回复保存失败并返回 409。现在仅合并独立的图片队列和媒体变更；真实健康资料、关联图片或对话被并发改动时仍拒绝覆盖。
2. 自然聊天先请求纯文字，再串行请求一次资料提取。真实测试复现回答约 38 秒返回后又等待 25 秒，第二次请求超时。现在用一次轻量 JSON 同时返回自然回复和有原文证据的事实，保留原有事实校验、保存设置及方案授权边界。兼容纯文字返回，直接展示并说明资料结构缺失，不追加请求。
3. 调用者的短超时只限制外层等待，底层 HTTP 仍可按 75 秒继续占用并发名额。现在剩余总预算会传入实际传输和后续重试；零预算不会启动网络请求。Android 传输另设截止定时器断开连接，仍使用系统证书校验。
4. 图片识别完成后原先还要调用文字模型整理，延长等待并与前台问答争用同一份状态。现在直接发布视觉报告，按现有规则处理明确食用说明；前台问答进行中时延后本地发布，不消耗重试次数，也不重新识图。只上传图片不会被认定已食用，不据图片自动生成计划。
5. 等待文字回复时，计时器每秒删除重建提示节点。现在只更新阶段和秒数，保留展开的进度详情。图片等待保存的提示也与实际阶段一致。
6. Android 设置页恢复内置模型后关闭旧设置窗口，避免再点保存把窗口中旧地址和旧密钥覆盖回去。

保留 0.4.26 的视觉独立预算：180 秒传输、205 秒外层预算。背景见 [0.4.26 交接](HANDOFF_2026-10-08_PHONE_TEST_0.4.26.md)。

## 验证证据

- 288 项 Python 回归全部通过；新增并发队列与文字保存、媒体删除不复活、关联图片/健康资料冲突保护、报告直接发布、前台优先保存、单次资料提取及实际传输预算测试。
- 当前 `https://cc-vibe.com/v1`、文字与图片均 `gpt-5.5`：通过本地 HTTP 流式进度接口连续进行三轮问答，同时排队分析两次用户提供的截图。问答均无 AI 错误或资料提取错误，耗时 57.922、5.609、7.781 秒；两次图片任务分别约 13.8、12.9 秒，均成功并有报告，摄入记录为零。
- 这次完整流程共三次文字请求、两次视觉请求，没有额外的资料提取或图片整理模型调用。安全结果记录在 `tmp/request-audit-live-0.4.27.json`，不含密钥。
- Edge 390px 页面验收：连续两次上传均显示报告，缩略图稳定；完成状态读取失败后能够重试，结果按钮定位正确。
- Edge 文字交互验收：等待节点保持稳定、进度详情展开状态保留；中文输入法确认不会误发送，两轮回复刷新后仍存在。
- Edge 完整页面验收：档案年龄保存及刷新、单对话导出、计划入口、相机大图压缩、报告编辑、明确食用后只保存一条餐食、撤销摄入及无效图片提示通过。初次复用页面测试服务时，旧测试脚本误把既有图片的完成状态当作新任务完成；已改为按本次 `client_job_id` 等待并在全新临时数据服务上重跑通过。
- release 构建及 lintVital 通过；APK 的 29 个公开引擎文件与源码逐字节一致，内置密钥与当前 Windows 用户环境变量一致，源码临时明文资源已清理。

速度仍取决于当前服务，首轮问答实测接近一分钟；本次无法承诺每次都快速返回。没有连接 Android 真机，不能以桌面验收代替用户手机网络和 WebView 的最终验证。
