# 知衡 0.4.38：语音录入完成与发送恢复

用户反馈只能录音，不能转换到输入框，也不能发送；补充确认“没看到结束按钮，发送一直不能点”。检查发现旧界面将中间识别结果放在提示区，输入框只等最终回调；同时发送按钮全程禁用，停止入口在另一个不断变化的语音按钮上。另一个可确认的实现风险是 UI 线程直接调用 AudioRecord.stop，部分设备上可能阻塞。没有实机证据说明用户遇到了此阻塞。

## 行为变更

- 识别中的文字实时显示到输入框，修改后的假设替换上一预览，保留录音前草稿。文字仍需用户核对。
- 聊天框右侧主按钮在收音时显示“完成录入”，点击后结束识别，不自动发消息；结束后按钮恢复“发送”，输入框恢复编辑。原语音按钮也能完成录入，回车遵循相同流程。
- Vosk 输出非空的完整分句后再停顿 1.5 秒，可自动结束；这不是从最后一个音节起算的固定时间。如果继续讲话产生新的非空 partial，会取消待执行的结束。
- 结束处理最多等待 15 秒，之后恢复编辑与发送。有预览时保留并提醒核对；没有预览时保留原草稿并提供重试/输入法语音入口。旧回调不能覆盖修改后的草稿或新的录入。
- 主动取消恢复录音前草稿。准备期间仍可取消；准备未完成前不会将音频假装为识别文字。
- 麦克风改为非阻塞读取，停止和取消通过会话标志通知后台线程；AudioRecord.stop/release 与识别器清理在后台执行，避免阻塞 WebView 所在 UI 线程。
- 中文离线模型、对话与图片模型配置保持当前设置。语音转文字不依赖外网，发送给远程对话模型仍需联网。
