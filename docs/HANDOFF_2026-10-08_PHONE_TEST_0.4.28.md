# 知衡 0.4.28：恢复减重主动引导

用户反馈 0.4.27 能连接，但表达减肥意愿后不主动提问、不带着了解情况。本次恢复主动减重咨询，同时保留上一版请求与图片队列修复。

## 问题与改动

- 旧路由将“我想减肥”默认设为闲聊模式，清除连续评估状态；闲聊提示词又限制补充档案提问。这使明确的个人减重意愿难以进入后续了解流程。
- 现在个人减重目标默认开始主动了解；“怎么减肥”“如何减肥”等请求也能进入此流程。先结合本轮信息回应，再问下一项影响建议的情况，覆盖基础、目标、健康限制、饮食饮料、睡眠作息、活动及以往执行困难。已回答的项目不反复问，用户一次补充多项时一并接收。
- 评估中模型只给泛泛回应、没有下一步问题时，程序会补上尚未了解的问题；“继续”保持咨询状态。资料充分后展示可更正的事实摘要，确认后进入个体方案生成。
- 旧版被默认设成闲聊的减重会话首次继续时恢复引导；历史中有明确要求暂停或只解释的会话仍尊重该选择。用户重新提出减重请求可开始主动了解。
- 明确要求暂时聊天、只解释、暂停或更正时先处理该请求；个人资料仍按原文证据和用户保存设置处理。
- 实测摘要暴露了资料提取细节：初始“想减肥”没有被后续目标体重具体化，加班吃多被归为职业，常见睡眠遗漏起床时间。已修复目标细化、职业识别及完整睡眠时段，并按原话提取实际活动、可用时间和上下班安排。
- 补测摘要确认后的方案生成时，复现本轮体重已在事实检查点保存，但摘要版本又包含候选体重，导致确认被错误识别为过期。现在展示的摘要和版本绑定最终校验后的实际保存事实，包括最终记录 ID 与时间；确认后提示模型直接生成方案，避免重复要求确认。
- 超时重试曾因原始请求被目标体重陈述替换而丢失评估路由。现在按已保存的个人减重会话状态恢复，重试和数字补充不依赖原话中是否仍有“减肥”两个字。
- 已核实资料足够时，程序直接展示本地事实摘要，不等待模型重述；实测此步约 31 毫秒完成。待核实的档案变更会在对话中展示原值和新值，明确询问“用新记录”或“保留原记录”，处理后核对最终摘要。“确认”与这两种选择不会被存成餐食或其他健康事实。
- 餐食描述不再覆盖已有饮食偏好；一次补充三餐时分开保存，睡眠与工作安排也分开保留。明确“没有用药”由本地规则提取；用户转讲饮食或作息时，不因上一问是用药就把该段话保存为药物。
- 正式方案现在使用单独的简短输出约定和已确认事实，减少旧超时通知、行政选择和重复对话对生成的干扰，并保留完整结构的输出预算。
- 完整实测发现旧“全档案填完”判断会在必要资料已齐、摘要已确认后静默丢弃模型计划。现在个人减重方案统一使用决定相关的资料要求；用户明确要求先完善档案时仍保留该流程。模型只口头回应却没有问题或可保存计划时，明确标记 `AI_PLAN_MISSING`，提供继续请求入口，不显示成已完成方案。
