# 知衡 0.4.39：按健康 Agent 的使用方式修正对话和图片流程

用户反馈：同样的问题问多遍；拍食物主要想获得吃多少、怎么搭配、整份吃完的影响，却一直被问吃没吃；初次了解逐项盘问，整段回答后仍重复；界面不好用。用户再次明确产品是持续了解自己的健康 Agent，兼顾营养、健身、报告解读和合理的检查/就医方向，支持文字、语音、图片。

本轮先阅读最新 0.4.38 交接及此前对话/图片记录，再检查实现。0.4.38 主要处理语音，不能证明整体对话达到要求。本轮不是更换模型；修正了控制模型输出的程序流程。

## 确认的原因

1. 多处提示限定一次一个问题；程序把多字段提问判成问卷，重新改为单字段提问。旧测试甚至要求每轮必须继续追问。
2. 部分资料已提取，但回答校验发生在提取完成前；缺少通用的本轮事实核对。旧历史上下文只保留最近 12 条、每条 1200 字。
3. 旧减重访谈状态可能因本轮带数字或回答饮食而恢复，抢掉用户新问题；在资料凑齐时把“比较晚餐”覆盖为正式方案前的摘要确认。
4. 食物图片提示默认追问，视觉请求没有带已存档案和当前聊天背景；发布阶段只展示 summary、热量和 question，advice 留在详细报告中。
5. 饮食正文超过 260 字或多于两个列表项就被模板替换。真实模型补测发现，这会把有用的长比较变成又一次询问“食堂、外卖还是做饭”。

## 本轮实现

- 统一健康助手角色与交互原则：当前请求优先；初次只说想减肥，合并了解未知的年龄、性别、身高、体重和目标。相关健康限制也可合并，允许整段回答，不强制每轮提问。
- 保留有关的多问题回答和完整解释；只在模型空泛停顿时补上推进问题。不再用字数和普通短列表判定饮食回答失效；确有未核实商家/数值问题才使用原安全回退，并带上已知外卖条件。
- 增强分号、带空格、身高米单位和单独单位体重的识别；整段事实一起处理。回答发布前用已提取事实去掉完全已知的问题；基础信息混合提问只保留未知项。单个裸数字面对多个问题仍不随意归给年龄或身高；明确更正/近期变化核对保留。
- 当前餐食比较、解释、报告问题可暂时离开旧减重评估；“查户口、重复问、已经说过”等反馈会调整节奏。普通问题不自动确认旧方案摘要。
- 历史窗口扩大到最近 24 条、每条最多 6000 字；跨对话仍使用已保存的结构化档案与记录。没有新增无限历史记忆或完整语义检索，不能宣称所有细节永久记住。
- 图片识别加入已保存档案及该图片所属对话最近 8 条背景，不混入其他聊天。食物默认分析和吃前建议：营养特点、可见份量建议、搭配和整份考虑；不默认询问是否吃过。只有明确事实才计摄入的边界保持。
- 图片 advice 进入聊天正文，食物热量仍来自程序校验后的结构化合计/部分合计。旧模型返回的食用确认问题不会在发布时强制追问。报告解读建议也进入正文。
- 聊天页面改为紧凑标题、自然对话与固定输入框；空白页提供减脂、餐食、运动、报告四个入口；入口先填草稿，用户发送。历史改为可搜索弹窗，记忆折叠查看；保留图片结果弹窗、编辑、语音完成录入与手动发送。
- 界面参考了 [Chatbox 的界面说明](https://releases.chatboxai.app/zh/guide/getting-started/interface-overview) 中对话区、输入区与会话入口的组织方式，没有接入或复制 Chatbox 的服务。
