# 0.4.0 建档、餐次评估、照片上传与开始引导

## 目标

按实际咨询流程完成了解、保存、评估、计划、执行反馈，避免只将用户给的例子机械放入计划。此版本改善产品流程，并不代表取得营养诊疗资质或已验证所有模型建议的专业质量。

## 档案漏记

- 补上旧对话/模型自由提问的上下文解析。上一轮单独询问年龄，回复 `38` 可确定性保存；明确的编号问题与编号回答也可以对应。多个字段混在一个问题里时不猜测裸数字含义。
- 每个字段独立校验，某个字段无效不会导致其他有效答案一起丢失。
- 聊天显示“实际已保存的档案”及待核实数量；年龄在聊天摘要与档案页刷新后仍可见，保留原话来源。
- 档案编辑区增加“从历史回答查漏”：仅找明确可对应的年龄、性别、身高，缺失项目进入待核实区，由用户确认；不覆盖已有资料，不猜测病史。
- 对不完整答案继续补充时，保留前次原话并附上补充，避免无意义的冲突。含糊的“18年切除了”必须再问具体手术，不能推断器官。

## 餐次评估

- 早餐、午餐、晚餐分开了解食物与份量；新增饮料/加餐/酒、饥饱感与进食困扰、体重变化和减重经历。
- 菜名不等于完整餐次。只答“面条”会问份量；用户可用碗、杯、个描述，也可明确跳过未知内容。
- 模型不能凭早餐原话填午餐，也不能将“面条”扩写成用户已吃“100克面条”。资料依据保留用户证据。
- 结合已有疾病用药、过敏、手术、作息、通勤、活动基线、时间、预算和偏好，先选择1–2项可执行改变，说明原因与替代方案，约定反馈和复盘。
- 提示词约束：默认一周试行；不把“一碗”改写成“满碗”，不将碗/拳头武断换成生重克数，不凭未知份量断言摄入过多；不用未经计算的精准热量或消耗数字充当个体处方。

## 开始及次日引导

- 计划生成后明确说明开始日期，默认明天开始。
- 保存开始清单：起床后反馈睡眠、身体感受，方便时记体重；早餐前说明当天安排和可选食物，已吃过则记实际摄入；各餐补充份量；晚间反馈饥饿感、活动、执行困难，一周复盘。
- 聊天和计划页展示清单，并提供开始反馈入口。这是打开应用时的引导，不是后台推送通知。

## 照片上传

- 新增浏览器侧解码、限边缩放和 JPEG 重编码。饮食照片最长边2048，报告3000；处理文件类型为空、大尺寸、JPEG附加动态照片尾部数据等情况。上传的是处理后的分析副本，相册原文件不修改。
- 超过40 MB、无法解码、转换失败、上传失败会留下可见错误，不再只显示短暂提示。后台分析失败展示具体错误码和重试入口。
- 用户尚未提供其手机具体错误文本，因此不能断言已经定位该手机拍照失败的唯一根因。当前无连接安卓设备，本轮未验证物理相机、厂商相机回传或进程被系统回收后的行为。
