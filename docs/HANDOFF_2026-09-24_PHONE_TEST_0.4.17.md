# 知衡 0.4.17：连续初诊对话体验

日期：2026-09-24。用户希望首次减重咨询能像一次真实、连续的营养咨询：接住本轮信息与疑问，沿目标、基础信息、健康限制、症状、典型饮食、作息与执行困难逐步了解，再核对事实并制定方案；餐图需说明识别项、粗略区间、假设与来源。0.4.16 虽修复重复问基础资料与过早保存方案，真机体感仍差。本轮修复集中在初诊续聊和最终显示回复，不把用户真实病史、餐照或对话导出写进仓库。

## 主要原因

1. 原提示词在评估未完成时仍向模型展示完整计划结构和大量建档字段，诱导长问卷或提前生成建议。现在初诊使用独立、短得多的咨询契约：`plan:null`，先回应当前具体情况，再问一个最有价值的主题；正式计划结构只在达到门槛后使用。
2. 用户回答开放式健康问题时，程序有时把陈述判为普通聊天，失去个体减重安全门槛。真实模型测试中，这曾使成套饮食/运动建议作为正文直接出现。现在只要上一轮仍在初诊提问、这轮是陈述回答，就继续初诊校验；普通独立问答仍可中断。
3. `asked_field` 曾把包含病史、手术、药物的整段回答塞入一个健康字段。现在对明确自述的健康事实分字段提取，混合回答不当作一个字段；未提供的性别不能凭模型推断入档，目标和基础数字也改用原话验证。
4. 模型会回到旧问题、在用户主动转谈工作/饮食后追问性别，或把久坐说成体重上涨的确定原因。应用现在识别这类偏题/过强结论，转而接住当前限制并问相关问题；已有问题留待后续。运动中头晕等新症状优先于普通建档缺项，继续提示停止诱发活动和线下评估。安全措辞参考 [美国心脏协会的运动警示信号](https://www.heart.org/en/health-topics/cardiac-rehab/getting-physically-active/develop-a-physical-activity-plan-for-you)。
5. 模型偶发无效 JSON 或超时会让对话直接出现技术错误。初诊现在在这两种失败下保留模型失败诊断和重试入口，同时用已确认事实给一个安全、本地生成的下一问；超时会明说“模型这次响应超时”。不把失败伪装成模型成功。

## 验证与边界

- 254 项 Python 回归通过，含新对话的裸数字年龄/身高、混合健康回答、未说性别不得入档、开放回答保留初诊门槛、模型长清单/无效 JSON/超时的回退、用户转谈作息后不拉回旧问题。
- 用**虚构资料与临时数据库**连续调用当前 `claude-opus-4-8` 七轮：最终测试中七轮均连接成功、未提前保存正式方案；健康信息分字段入档，未编造性别；工作时间话题被接住，回复没有声称久坐是确定原因。另一次独立测试出现上游超时及一次无效 JSON，因此不能把模型稳定性当作已解决；新的本地接话回退由隔离回归验证。
- 这次没有换模型。真实测试表明主要失误包含应用把初诊回答误分流、模型输出未受应用校验、上下文焦点丢失；直接换模型不能替代这些修复。现有模型仍可能有生硬措辞或需要再问的信息，只有用户真机测试才能判断体感是否接近目标。
- 餐图的粗略营养区间、来源展示与多人分食规则沿用 0.4.15，未在本轮重新验证真实餐馆照片的识别精度。麦克风真机体验也不在本轮代码范围。
