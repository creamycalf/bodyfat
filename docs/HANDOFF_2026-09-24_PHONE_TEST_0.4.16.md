# 知衡 0.4.16：新对话重复问基础资料、过早给方案

日期：2026-09-24。用户在 0.4.15 真机新建对话中反馈：年龄和身高反复被问，仅回答少量基础数字后就收到成套建议。本轮按新对话复现并修复；真实手机体验仍由用户验收。不要把用户实际健康资料或导出的真实对话写入仓库。

## 原因与改动

- 多字段问题如“年龄、身高和性别是什么”没有单一 `asked_field`。用户只回 `38` 时无法安全映射到年龄，下一轮又认为年龄缺失。现在基础资料缺项时，若模型提出多字段问题或重复已知字段，应用改为一次只问一个明确缺项，并记住当前提问字段。纯数字回答会落到该字段；保存后再问下一项。
- 首轮“我目前体重 200 斤，想减肥”此前可能因为同一句出现“想”而整句不保存当前体重。现在只排除数字前的目标语境，不丢掉明确的当前体重。
- 模型以 `plan:null` 返回的整套“饮食原则/减肥建议”也可能绕过计划保存门槛。现在缺少个体减重评估资料时，结构化计划、长清单和带频次/定量处方的正文一律改为一项低风险起步观察加一个缺失问题。正式个体方案仍须完成健康史、饮食、作息和执行条件评估，并核对事实摘要；仅有年龄、身高、体重不能放行。
- 安全资料缺失时，继续优先问疾病与不适、用药、过敏、手术恢复；已知年龄和身高不再作为后续问题。

## 验证

- 246 项 Python 回归通过。新增虚构多轮新会话：当前体重 → 裸数字年龄 → 性别 → 裸数字身高 → 病史问题；检查已答字段不重问、计划未保存。另测档案已有年龄/身高的新对话，即使模型重问，最终回复仍改问健康史。
- 使用隔离临时数据库、虚构三轮初诊调用当前 `claude-opus-4-8`：模型连接正常，三轮均未保存方案。模型第二轮原始文本仍列了多组问卷，应用最终回复收敛成单一健康史问题；这说明问题不只在模型，应用层需要持续兜底。该小样本不代表手机上的完整自然度验收。
- Android release 编译及 lintVital 通过。APK 版本 `versionCode 24`、`versionName 0.4.16-test`；签名有效且与 0.4.15 相同。29 个公开引擎文件与源码逐字节一致，内置服务地址为 `http://47.110.38.211:8080/v1`，模型名和密钥与受控环境一致，未打印密钥；临时明文源码资源已清理，APK 未包含项目 `.data` 或签名私钥。
