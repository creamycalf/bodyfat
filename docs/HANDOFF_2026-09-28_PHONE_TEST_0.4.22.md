# 知衡 0.4.22：重复图片上传与结果显示修复

用户反馈第一次图片正常，第二次持续闪烁且只显示完成；同时询问如何换模型。本轮没有读取真实健康资料，没有更换内置默认模型。

## 定位与修复

- 复现：任务列表每3秒清空并重建全部缩略图，已完成任务也如此。浏览器连续上传两张同样的合成图片，两份报告均存在，但原缩略图节点在轮询后被移除。修复后未变化的卡片保留，只更新发生变化的任务。
- 完成状态被缓存后，如果刷新对话失败，下一轮因为状态未变便不再刷新。现在仅成功读取结果后清除待刷新标记；失败提示自动重试，不只显示已完成。
- 「查看分析结果」主动重新读取状态，打开关联对话并定位对应图片消息。已完成任务卡不再只是无法定位结果的状态提示。
- 手机第二次完全不分析尚未真机复现，不能声称已证明模型或队列没有其他问题。本次关闭的是已复现的闪烁、结果刷新失败后不恢复两个问题。

## 模型配置与试用建议

手机顶部「AI 设置」直接修改模型名称与图片模型，协议选择 `chat_completions`。沿用现有服务时，接口为 `http://47.110.38.211:8080/v1`，密钥框留空保持已保存密钥。保存后再点「测试已保存的模型连接」；这个按钮仅测试文本连接，不验证读图或分析质量。

电脑配置在项目根目录 `config.json`，密钥从其 `api_key_env` 指定的受控环境读取。手机配置不从电脑文件自动同步，而是保存在应用私有 SharedPreferences 中的加密值；通过界面修改，无须寻找明文配置。

当前服务列表提供 `claude-sonnet-4-6`。可以把对话和图片模型都改为此名称进行对照，但只是当前服务别名，不证明官方上游身份或更高质量。`tests/qa_model_image_candidates.py` 用两张人工生成的四位数字图分别请求此别名与 `claude-opus-4-8`，两者各2/2识别正确；报告 `tmp/model-image-candidates-20260928.json`。只证明本次简单图片请求可用，不证明营养估算、复杂报告识别或自然对话更好。模型列表中没有GPT/Gemini名称，不建议在当前服务盲填。
