# 餐食定位、修正预览与撤销交接

2026-09-16。本文件为最新交接入口，继承 `HANDOFF_2026-09-16_DATA_CORRECTNESS.md` 的语义防误写修复及其限制。

## 使用流程

- 档案 → 查找与修正餐食：按实际用餐日期和餐食描述关键词筛选。
- 看板 → 查看已记录餐食，或档案的实际健康记录 → 核对 / 修正这餐。
- 核对日期、描述和原图。可修改日期/描述，或明确撤回未吃的餐食。
- 营养处理默认设为待核实；只改文字/日期时可保留估算，同样食物调整份量时可按修正前记录的倍数换算。未知营养仍未知。
- 先预览前后变化，再确认保存。记录 ID 和关联照片保留；撤回摄入不删除照片。
- 档案 → 餐食修正历史，可刷新后查看前后对比并撤销。若记录或照片已发生后续变化，阻止撤销覆盖新数据；其他餐食新增不影响该餐撤销。

## 实现

- `meal_records.py`：预览、校验、提交幂等、记录/媒体冲突检查、持久历史及撤销。
- `product.py`：work/action 新增 meal_preview、meal_commit、meal_undo；快照提供 meal_corrections。
- `meal-records.js`：日期/关键词定位、原图与前后对比、确认保存及撤销。
- `archive-tools.js` 接入入口；`health-pages.css` 对话框手机适配；`server.py` 静态路由。
- 预览没有业务数据写入；提交 token 绑定原记录、原媒体、规范化结果及该记录修正历史。预览后记录/图片变更或提交内容被替换会被拒绝。
- 历史存于 workspace.meal_corrections，随现有存储及导出持久化。撤销同时恢复该次修改前的关联媒体状态。

## 边界与后续

- 本轮是明确选中记录后的人工核对流程，不自动解释“昨天那顿”等模糊对话指代，不根据描述重新估算营养。
- 相对倍数针对当前记录，不代表原图整盘份量；界面已明示。
- 多餐次复杂表达仍遵循上一轮保留原记录并追问的策略。
- 对话中的更正候选选择、食谱回填、后台页面恢复、跨版本语义匹配等仍未在本轮实现。
- 未向上游传输用户资料，未批量修正历史摄入。历史记录包含原始健康信息，应与其他健康数据一起保护。
