# 知衡 0.4.12：持续营养管理 P0 交付测试包

日期：2026-09-24。依据 [产品决策文档](NUTRITION_AGENT_PRODUCT_DECISION_2026-09-23.md) 收尾 P0 手机体验修复。此包供用户本人覆盖安装测试；尚未进行真机验收，也不代表临床建议已验证。P1 的依据与指南审阅、P2 的真实菜单接入、P3 的长期局部修订仍是后续阶段。

## 相比 0.4.11 的修复

- 对“200 斤想减到 150 斤”类请求，在资料不足且模型输出长问卷、过早认可目标或给出精确减重/运动时长时，改为说明未知、提供当下低风险观察步骤，并只追问一项会改变判断的信息。模型格式失败后，用户补充身高等数值仍可接续评估。
- 无真实菜单的外卖咨询不再展示模型臆测的具体附近菜品或店铺；提示可搜索的餐食类别，请用户提供正在看的候选。修复“没有菜单”被误判为已提供菜单的问题。
- 计划的可选起步提示只取生效当天实际安排的行动；过了生效日不再反复展示。模型被替换为澄清回复时，工作流状态保留为“澄清”，不误报无操作。
- 继承 0.4.11 的当日餐次判断、明确日期尊重、自然回复保留、第三天复盘分流与条件化自做/外卖选项。

## 验证

- 229 项 Python 回归通过；包含无菜单短回复、体重目标逐轮追问、模型失败后的接续、日期与行动引导、既有安全和持久化流程。
- JavaScript 语法检查通过；390px 隔离界面流程通过，覆盖档案、计划、照片、报告修改、摄入确认/撤销和错误提示。
- 使用隔离合成资料对指定远程模型跑通 5 组场景：体重目标两轮、晚间无菜单外卖、早餐已知后询问午餐、夜班且不想做鱼、计划第三天加班复盘。回复未强迫改为明天开始或生成新通用计划；无菜单场景明确说明商家与份量不可核实。场景集只验证这些输入，不代表长期质量。
- Android `assembleRelease` 成功。包名 `cn.zhiheng.mobile`，`versionCode=20`，`versionName=0.4.12-test`；签名与 0.4.11 相同。APK 内 28 个程序资源与源码逐一匹配，模型配置含指定基址 `http://47.110.38.211:8080/v1`、模型名称及受控密钥；未打包项目 `.data` 健康资料或签名密钥，源码临时明文配置已清理。
