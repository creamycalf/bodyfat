# 对话驱动产品改造实施基线

> 最新用户反馈、修复与当前运行状态见 [产品改造交接](HANDOFF_2026-09-07_PRODUCT_V2.md)。本文保留前期阶段性验收，当前回归为 36 项；最后一轮看板展开改动尚未完成视觉验收。

2026-09-07。本轮依据 PRODUCT_REDESIGN_2026-09-07.md 及用户后续补充实施。

## 本轮已接入

- 四入口重新组织：对话负责理解与采集，看板显示持久计划和今日执行事项，档案显示个人背景、实际记录、待核实项与计划历史，我的负责设置和备份。
- 首次按减脂、睡眠、饮食或一般健康问题选择选填表单；保存或跳过后继续原始计划请求。采集状态随对话持久保存。
- 自然语言明确事实整理、模型提供带原文证据的字段建议，冲突或不确定项进入待核实区；支持逐次确认设置。
- 计划生成后持久保存，区分建议中和执行中；支持启用、暂停、每日完成/部分完成/跳过反馈、版本调整。
- 新增 SQLite 事务存储。采用 documents 表保存逻辑文档对象，保留旧 API 适配；并非设计稿中的完全规范化多表。事务实现跨对象提交和版本冲突检查，消息 ID 防重。
- 首次启动生成迁移前 ZIP 后导入既有 JSON。原 JSON 保留作迁移来源，运行后以 SQLite 为准。备份导出一致的逻辑 JSON，恢复时重建 SQLite，避免直接复制打开的数据库。
- 前端拆成 index.html、app.css、app.js、voice.js。语音支持浏览器中文识别、停止/取消、草稿保留、错误提示；不支持识别的浏览器有明确提示，无虚假平台承诺。

## 当前验证

35 项 Python 自动化测试通过；前端模块语法通过。新增测试包括场景表单继续生成计划、档案落盘、去重、事务回滚、假设不写入、撤销、执行反馈及备份恢复。

浏览器与真模型验收使用 tmp/product-qa/.data 隔离数据目录及 8791 端口。上游首次返回 Markdown 而非 JSON；提高工作流输出额度到 4000 并在请求末尾明确 JSON 约定后，真实调用成功返回计划，耗时 74328 ms。不能将最初失败简单归因为 token 限制。浏览器验证计划在看板展示、点击完成后保存、档案显示已填资料。普通旧对话请求保留原输出额度。

正式 8787 服务已切换新版，迁移前备份为 `.backups/pre-sqlite-20260907-120557.zip`。迁移后核对：原档案一致，3 条记录、4 段对话保留；正式数据没有写入虚构测试计划。当前为后台直接 Python 进程，不是系统服务或自动开机任务。

语音模块用 Node 验证草稿保留、取消、网络失败及无识别接口提示。原图管理、数值修正、记录记忆开关和体重趋势已接回新版。

## 尚需完善和明确限制

- 浏览器实际语音服务受系统、网络与权限影响，尚未完成人工麦克风收音验收；没有配置独立后端转写服务。
- 复杂自然语言纠错、跨日延期、任意组合反馈、计划差异确认和细粒度撤销还需继续扩充。当前撤销仅在无后续变更时允许，以防覆盖新数据。
- 计划在 SQLite 中以文档对象保存，尚未拆成独立关系表；数据量大后需优化。
- 图片仍走原识别接口，结果需核对后发送；完整结构化图片确认卡需要进一步完善。
- 无登录或多用户隔离，保持可信本机单用户边界。

产品验收必须区分已通过的功能和上述限制，不能宣称整个设计稿已全部交付。
