# 系统架构

## 1. 组件

| 组件 | 文件 | 职责 |
|---|---|---|
| Web 前端 | `index.html` | 对话、候选确认、看板、档案、资料和图片管理 |
| 正式后端 | `server.py` | HTTP API、数据持久化、模型调用、记忆检索和安全规则 |
| Mock 后端 | `server.mjs` | 无真实模型的旧版演示，不用于正式验证 |
| 配置 | `config.json` | 本机 AI 和存储配置，不提交 |
| 示例配置 | `config.example.json` | 无密钥的配置模板 |
| 数据目录 | `.data/` | JSON 档案和原始媒体 |
| 测试 | `tests/test_server.py` | 后端逻辑回归测试 |

## 2. 主要流程

```text
用户输入
  → 本地紧急关键词检查
  → 品牌/内部配置询问本地拦截
  → 必要时邀请填写可选资料表单，或继续文字/语音
  → 本地相关记忆检索
  → 远程模型或本地规则降级
  → 生成回复和候选字段
  → 用户修改/确认
  → 原子写入档案
  → 刷新看板、趋势和建议
```

紧急关键词在调用远程模型前处理。胸痛、呼吸困难等情况直接返回就医提示，不等待网络。

资料采集表单由前端固定定义，触发信号可以来自本地规则或模型的结构化 `intake_form` 字段。表单提交走独立的 `/api/intake`，不让模型决定字段校验或直接写入数据。用户选择跳过后，模型一次最多追问一个问题。

## 3. 模型调用

后端兼容 Responses 和 Chat Completions。当前正式配置固定使用 `chat_completions`，避免自动探测造成额外请求。

- 最大并发：3；
- 超时：默认 35 秒；
- 重试：配置值限制在 0–2 次；
- 401/403 不重试；
- 429 和 5xx 可有限重试；
- 每次响应带 `request_id`、耗时、尝试次数和安全错误码。

模型输出优先按 JSON 解析；无法解析时保留文本回复，并使用本地候选提取结果。

## 4. 长期记忆

只有同时满足以下条件的记录才进入检索：

1. `confirmed` 为 `true`；
2. `memory_enabled` 不为 `false`；
3. 与当前问题的记录类型或关键词相关。

检索在本机完成，按类型匹配、关键词重叠、记录时间和顺序排序。单次最多向模型提供 12 条记录，只包含 `id`、`type`、`value` 和 `created_at`。前端显示命中原因。

当前不是向量检索，近义表达能力有限。

## 5. 数据写入

- 单条写入和批量确认都会经过记录类型与数值范围校验；
- 批量确认是一次原子写入；
- 撤销令牌只可使用一次，有效期 120 秒；
- 睡眠范围为 0–24 小时；
- 体重范围为 20–400 kg；
- JSON 文件通过 `.tmp` 文件替换写入。

## 6. 前端状态

前端从 `/api/bootstrap` 获取资料、记录、对话摘要、媒体和看板。页面不再使用虚构健康数据。接口不可用时，聊天可以退回前端规则提示，但无法持久化或刷新真实档案。

表单选择状态 `intakeMode` 仅在当前页面会话保存：`chat` 表示使用对话，`submitted` 表示刚完成表单。确认资料由服务端 JSON 文件持久化，页面刷新后重新预填。

## 7. 当前边界

数据目录使用 `metadata.json` 记录版本。启动时执行幂等迁移，迁移前生成完整回滚备份；恢复旧备份时会在隔离目录升级到当前数据版本后再替换正式数据。

服务只绑定 `127.0.0.1`，CORS 只允许本机 8787 来源。当前没有用户认证、数据库、加密、后台任务进程或多实例一致性设计，不应直接暴露到公网。
