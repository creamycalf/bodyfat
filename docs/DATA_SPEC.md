# 知衡数据采集与媒体资料规范

## 1. 总原则

不是所有可采集的数据都值得每天采集。每种数据必须满足至少一个条件：

- 能改变今天的决策；
- 能解释体重或症状趋势；
- 能帮助医生复核；
- 用户提供成本很低。

图片或语音只产生“候选记录”，必须经过用户确认才进入长期档案。图片识别结果保留范围、置信度、来源和用户修正值。

## 2. 数据优先级

### P0：第一版必须支持

| 数据 | 方式 | 频率 | 进入档案的字段 |
|---|---|---:|---|
| 体重 | 手动、秤屏幕照片、后续设备 | 每周3-7次 | kg、时间、来源 |
| 腰围 | 手动 | 每周1次 | cm、测量位置、时间 |
| 熟食/外卖 | 照片+对话 | 每餐 | 菜品、份量、热量范围、实际吃了几成 |
| 饮料 | 照片、文字、条码 | 每次 | 品类、容量、含糖/酒精、热量 |
| 睡眠 | 对话或后续设备 | 每天 | 入睡、起床、夜醒、主观质量 |
| 精力/饥饿 | 快捷选择或对话 | 每天 | 1-5级 |
| 症状 | 对话 | 发生时 | 类型、严重程度、起止时间、是否加重 |
| 用药变化 | 对话/手动 | 发生时 | 药名、剂量、开始/停止、原因 |

### P1：有用但不必每天

- 血压、空腹血糖、尿酸等家庭测量；
- 体检报告或检验单照片；
- 每月一次正面/侧面体型照片；
- 步数、久坐时间、运动记录；
- 排便结构化记录；
- 本人明确提供的既往治疗后症状、饮食耐受及其关联；
- 医生要求复查的具体指标与原报告结果。

### P2：只在必要时开启

- 排泄物照片；
- 皮疹、伤口或身体局部照片；
- 详细家庭病史文件；
- 连续血糖、心电图、血氧原始文件。

这些数据高度敏感或容易误判，默认关闭，只有用户主动开启或医生要求时使用。

## 3. 图片类型和处理方式

### 3.1 体重秤屏幕照片

可以支持 OCR 读取数字，但必须显示：

```text
识别：99.8 kg
可信度：高
来源：秤屏幕照片
[确认写入] [修改]
```

不能把体脂率、内脏脂肪等级等消费级秤指标当成医学结论。拍摄失败时回退到手动输入。

### 3.2 体检单/化验单照片

AI只负责提取：项目名、结果、单位、参考范围、日期、医疗机构和报告页码。用户确认后才保存。

```text
尿酸  ·  468 μmol/L  ·  参考范围：...  ·  检测日期：2026-08-30
[确认] [修正] [不保存]
```

AI可以说明“需要和医生讨论”，不能仅凭一张报告诊断疾病或自行改药。

### 3.3 熟食和外卖照片

输出热量区间和最大误差来源，优先追问米饭、油、酱汁、饮料及实际吃了几成。吃完后可补拍剩余食物，用来校准真实摄入。

### 3.4 生鲜和食材照片

照片只能识别“可能是什么”，不能可靠计算热量。必须结合：

- 重量（克）；
- 包装营养标签或条码；
- 生重/熟重；
- 是否加油、糖、酱料；
- 实际食用比例。

因此食材页面应先问“重量和烹饪方式”，再计算；没有重量时只给粗略范围。

### 3.5 身体照片

可用于每月体型变化对比，不应从自拍推断体脂、疾病或“内脏脂肪”。默认本地保存，用户可以设置自动删除。

### 3.6 排泄物照片

不作为日常打卡。更适合先用结构化选项：次数、稀/硬、颜色变化、疼痛、血、黑便、油脂漂浮等。出现血便、黑便、持续腹泻、剧烈腹痛等情况，直接提示就医，不用等待 AI 图像分析。

尿液也优先记录颜色、频率、疼痛、血尿和饮水量；照片只在用户主动选择时上传。

## 4. 媒体处理流水线

```text
照片/语音/文字
→ 媒体分类（食物、体重、化验单、身体症状、其他）
→ 提取候选字段
→ 质量和敏感度检查
→ 显示范围、置信度和不确定性
→ 用户确认/修改
→ 写入结构化档案
→ 触发看板和风险规则
```

每个媒体对象保存：

```text
media_id、类型、拍摄时间、上传时间、来源、文件哈希、保存期限、识别状态、用户确认状态
```

## 5. 每日交互预算

默认每日最多主动询问3次：早晨状态、关键一餐、晚间简短复盘。只有异常或用户主动提供数据时增加问题。AI必须优先问“最能改变决定”的一个问题。

## 6. 医疗和隐私边界

- 所有媒体默认私有；敏感照片可只保留结构化结果；
- 上传前显示用途和是否发送云端；
- 原始体检单、排泄物和身体照片默认不进入 AI 长期记忆；
- 用户可以导出结构化档案，也可以单独删除原图；
- 风险预警优先于减重目标；
- 数据不能用于推断诊断、调整处方或替代医生。
