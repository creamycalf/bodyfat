# 2026-09-23 自然咨询与可靠记忆第一阶段交接

更新时间：2026-09-23。当前仍不是 Git 仓库；没有清理目录、初始化仓库、修改生产 `.data`、打包 APK、发布或接入外部付费服务。

## 本轮已实现

- `consultation.py` 增加请求分流：普通科普、单餐交流、正式个体减重方案、复盘和高风险问题不再共用同一建档入口。减肥期间的普通问题可以直接回答；早餐等具体餐食不自动升级成长问卷。
- 正式个体减重方案改为“当前决策所需信息”门槛。基础资料、目标/困难、安全边界、至少一个代表性餐次、活动/执行条件、体重或进食经历按组判断；睡眠等有帮助但并非所有饮食方案的硬门槛。孕哺阶段、手术与恢复只在适用或用户已提及时进入必要项。明确跳过/未知不等同于“没有”。
- 资料足够后不直接保存正式减重方案。应用生成已知事实摘要并写入 `assessment_state.summary_confirmation`，保存摘要、事实摘要哈希、请求消息和确认消息。只有用户明确确认且事实哈希未变化，正式方案才能通过服务端门槛。
- 档案事实更正会把旧值和旧来源写入 `workspace.profile_history`，状态为 `corrected` 并记录失效时间；明确要求撤回/删除某类档案事实时，当前值移除，历史状态为 `retracted`。更正或撤回会使此前摘要自动变成 `stale`，后续正式方案需重新核对。
- 普通问题不会消费尚未回答的咨询主题，原咨询主线仍可继续；现有跨会话问题恢复、跳过状态和已回答主题继续保留。
- 回复和后台整理增加明确边界：安全、非虚假宣称的自然回复可在计划结构校验失败时继续展示；响应增加 `request_kind` 与 `background.status/failed_operations`。失败的计划、页面或餐食写入仍不会伪称已保存，原有事实检查点、幂等重试和危险计划校验保留。
- `snapshot` 现在包含 `profile_history`，便于核对更正/撤回来源。没有把模型推测升级为确认事实。

## 关键实现位置

- `consultation.py`：`decision_kind`、`required_information`、`readiness`、`facts_digest`、`summary_text`、`confirmation_state`、`next_question`。
- `product.py`：摘要确认状态迁移与服务端保存门槛、普通问题中断咨询的处理、`set_profile_fact` / `retract_profile_fact`、后台失败状态。
- `tests/test_consultation_phase1.py`：请求分流、摘要确认后生成方案、事实更正使摘要失效、明确撤回、普通问题不吞掉咨询主线、后台失败保留自然回复。
- `tests/test_intake.py`、`tests/test_nutrition_reports.py`：原有验收更新为摘要确认流程和决策相关门槛。

## 已知限制与下一步

- 当前分类与必要信息选择是保守的确定性规则，真实模型表达仍需用更长的多轮对话集验证，尤其是含蓄计划请求、多人信息、连续更正和跨天恢复。
- 摘要确认已通过 API 返回和服务端状态生效，但尚未增加独立的可视化“逐项确认”卡片；当前通过自然对话确认或直接更正。
- `profile_history` 保存在 workspace 中，尚未做单独的历史管理页面。记录类事实沿用现有 `status/source_message_id/observed_at/valid_until`；本轮主要补齐档案字段的更正/撤回历史。
- 本轮没有接入营养数据库，也没有改变图片营养密度仍来自模型估计的限制。下一阶段按路线图实施有来源、可修正的营养计算；不要在未核验许可、来源和口径前导入第三方数据。
- 源码改动尚未重新打包 Android。历史 0.4.6 APK 不包含本轮实现，不能当作当前源码产物。
